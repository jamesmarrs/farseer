# Farseer power-supply BOM

Bill of materials for the power circuits drawn in `power-rails-schematic.pdf`
(generated by `gen_power_schematic.py`). Architecture: 7–18 V vehicle bus →
front-end protection → **two independent 3.3 V bucks**:

- **`3V3_CELL`** — dedicated buck (`U2`, sized for the 2G/EGPRS burst) → BG95-M3
  **Mini PCIe** socket.
- **`3V3_SYS`** — small buck (`U3`) → PIC18F57Q84 `VTG` + NEO-M9N.

Because the BG95 is the **Mini PCIe card** (input spec **3.0–3.6 V, typ 3.3 V**,
`Quectel_BG95-M3_Mini_PCIe_LPWA_Specification_V1.1.pdf` p. 2), the raw-module
3.8 V VBAT rail and its pin-local star network (ferrite + small MLCC arrays +
2× VBAT TVS) live **on the card** and are **not** on our board. Our board only
delivers a clean 3.3 V + bulk reservoir to the socket.

> Reference designators match the schematic. Values marked "≈" or "per
> datasheet" are starting points to finalize during schematic capture against
> each IC's own design procedure (TI WEBENCH / datasheet equations) — but the
> **part itself is still needed**; only its exact value is TBD. Quantities
> assume **one** BG95 card, **one** PIC, **one** NEO-M9N. Before ordering,
> verify: feedback dividers, inductor Isat vs peak current, converter
> compensation, TVS clamp vs each downstream absolute-max, and cap/fuse voltage
> ratings vs worst-case transient.

Parts that appear in both this file and one of the other three — the BG95 socket
group (§4) and the `3V3_SYS` distribution group (§5) — are the **same physical
components** viewed from the rail side here and from the subsystem side there.
Order once. [full-bom.md](full-bom.md) is all four BOMs merged into one ordering
list with exactly those overlaps resolved; regenerate it with
`python3 docs/gen_full_bom.py` after any change here.

Rebuild them all with **`./docs/build_schematics.sh`** (or name one, e.g.
`./docs/build_schematics.sh gnss`). Each generator writes an SVG through
schemdraw, which `rsvg-convert` turns into the PDF and PNG. Shared colours and
drawing helpers live in `schematic_common.py`, so all four sheets read the same
way. Any BOM change here should be followed by a rebuild — the drawings carry
reference designators only, and the values in these tables are the single
source of truth.

**Status column** answers "is this needed or just a suggestion?":

- **Req** — mandatory. The IC will not function (or is unsafe) without it. A
  switching regulator is an IC *plus* its inductor, catch diode, input/output
  caps, feedback divider, bootstrap cap, and (for `U2`) frequency-set and
  compensation parts. These are not optional.
- **Rec** — strongly recommended for robustness/EMC; the circuit may "work" on
  the bench without it but shouldn't ship without it (e.g. gate clamp, soft
  start, EMI filter).
- **Opt** — genuine design choice; include only if you want that feature
  (e.g. hardware UVLO divider, GNSS backup cap).
